## Что делает

Пользователь рисует **куб в перспективе двумя точками схода** (обычный способ построения куба на бумаге), а программа:

- находит точки схода из нарисованных рёбер;
- проверяет, лежат ли они на одной высоте (горизонте);
- проверяет, перпендикулярны ли направления в 3D;
- проверяет, соответствует ли глубина куба высоте;
- проверяет, попадают ли верхние рёбра в нужные точки схода.

Всё — **из самого рисунка**, без знания «правильного ответа». Плюс отображает **идеальный куб**, который получился бы при текущих параметрах камеры — для наглядного сравнения.



## Как построить куб

Четыре этапа, строгая последовательность. Инструмент переключается **автоматически**.

### 1. Стартовое ребро

Тапните и потяните **вертикально** (сверху вниз или снизу вверх). Это переднее ребро куба.

- Создаётся одно стартовое ребро. Больше нельзя.
- Цвет: **зелёный**.

### 2. Боковые рёбра ×4

Из верхней и нижней вершины стартового ребра проведите **по 2 ребра в стороны**. Всего 4.

- Снап к существующим точкам работает, если ребро начато **с пустого места** — так удобно цепляться за вершины.
- Цвет: **белый**.
- После 4-го ребра инструмент переключается на вертикали.

### 3. Вертикальные рёбра ×2

Тапните в любом месте и потяните вертикально. Сделайте так 2 раза для задних рёбер куба.

- **Не прилипают к соседним точкам** (кроме точного попадания < 4px).
- Цвет: **оранжевый**.
- После 2-й вертикали **автоматически создаются голубые точки** пересечения каждой вертикали с каждым боковым ребром — это вершины верхней/нижней граней.

### 4. Верхние рёбра ×2

Соедините голубые точки. Получится верхняя грань куба.

- Всегда ищут ближайшую голубую точку.
- Цвет: **голубой**.
- После 2-го ребра — «Готово ✓».

### Цвета точек

| Цвет | Значение |
|||
| Синий | Свободная точка |
| Оранжевый | Точка на линии (`onLine`, пока не используется) |
| Голубой | Авто-пересечение вертикали с боковым ребром |
| Жёлтый | Активная при редактировании |
| Оранжевый с кольцом | Активная, но с заблокированным X (вертикальная) |



## Интерфейс

### Левая колонка (сверху вниз)

Таблицы со статистикой. Видимость зависит от режима:

| Режим | Что видно |
|||
| `∅` (скрыть) | ничего |
| `Вал` (валидация) | только метрики валидации |
| `Всё` (полная) | углы рёбер, точки схода, вертикали, верхние рёбра, валидация |

**Все таблицы скрываются, пока ведётся линия.**

### Правый верхний угол

Два независимых прямоугольника **одинаковой ширины**:

1. **Статистика** — переключатель `∅ / Вал / Всё` + круглая кнопка `?` (справка).
2. **Текущий инструмент** — надпись (например, «Боковое ребро (2/4)») и переключатель `Стд / Ред / Пан`.

### Нижняя панель

Три группы с увеличенным отступом между ними (для удобства большим пальцем):

| Группа | Кнопки |
|||
| Слева | Ползунок FOV + текущее значение + кнопка `A` (авто-подбор) |
| Центр | `Гор` (горизонт) · `Куб` (идеальный куб) · `Кр` (окружности) |
| Справа | `↶` (отмена) · `↺` (сброс) |



## Режимы работы

Переключатель `Стд / Ред / Пан` в правом верхнем блоке.

### Стд (стандарт)

Рисование по четырём этапам. Инструмент переключается автоматически.

### Ред (редактирование)

Таскайте **точки**:

- Точки на вертикальных рёбрах (стартовое, задние) — двигаются **только по Y** (X заблокирован, отображается кольцом).
- Остальные точки — свободно по обеим осям.

После отпускания все метрики и точки схода пересчитываются.

### Пан (перемещение)

Сдвиг всего холста пальцем. **Не искажает математику**: `state.view` применяется только на рендере, а все вычисления идут в world-координатах, которые не меняются. FOV, валидация, точки схода — остаются те же.



## Метрики валидации

Все — **в процентах от `h_f`** (высоты стартового ребра). Это критично: 10px при `h_f=50` и при `h_f=500` — разные вещи.

| Метрика | Что проверяет | Идеал |
||||
| **Горизонт** | Обе точки схода на одной высоте | 0% |
| **Рёбра ⊥** | Горизонтальные направления перпендикулярны в 3D (только в ручном FOV) | 0° |
| **Бок. рёбра** | Концы боковых рёбер лежат на прямых «вершина → своя точка схода» | 0% |
| **Пропорции** | Куб, а не столб: глубина соответствует высоте | 0% |
| **Верх. рёбра** | Верхние рёбра уходят в одну из точек схода | 0% |

Цветовая индикация:
- `✓` зелёный — `ε ≤ порог/2`
- `⚠` жёлтый — `ε ≤ порог`
- `✗` красный — `ε > порог`

Пороги: 5% для большинства, 10% для пропорций, 5° для углов.



## Авто-подбор FOV

**Ключевая идея:** для любого правильного куба при любом повороте выполняется инвариант:

```
(x_L − cx) · (x_R − cx) = −d²
```

где `x_L, x_R` — координаты точек схода, `cx` — центр экрана, `d` — фокус в пикселях. Отсюда:

```
d = √((cx − x_L)(x_R − cx))
fov = 2·arctan((W/2) / d)
```

То есть **по двум нарисованным точкам схода** можно однозначно восстановить FOV, при котором рисунок «правильный по перпендикулярности».

**Как работает кнопка `A`:**

| Состояние | Ползунок | Индикатор |
||||
| Авто включён, VPs ещё не готовы | Заблокирован | `60°?` (жёлтый) |
| Авто включён, VPs вычислены | Заблокирован, показывает авто-значение | `65°` (зелёный) |
| Авто выключен | Разблокирован, ручной | `60°` (серый) |

По умолчанию авто **включён**.



## Идеальный куб (фиолетовый)

Кнопка `Куб` в нижней панели показывает **куб, который получился бы** при текущих параметрах камеры (FOV, поворот ψ, горизонт `cy`) и стартовом ребре как передней грани.

**Алгоритм:**
1. Взять ψ из одной из точек схода: `ψ = atan((cx − x_L) / d)`.
2. Задать 3D-координаты переднего нижнего угла: `X₀ = V_bot.x − cx`, `Y₀ = cy − V_bot.y`, `Z₀ = d`.
3. Построить 8 вершин куба с ребром `s = h_f · Z₀ / d`, повёрнутого на ψ.
4. Спроецировать обратно: `x_s = cx + d·X/Z`, `y_s = cy − d·Y/Z`.

Если ваш рисунок сильно расходится с фиолетовым — либо рисунок неточен, либо FOV не тот (переключите `A` в ручной режим и подкрутите).



## Архитектура

### Слои

```
UI (DOM) ──────► Interaction (pointer events) ──────► state (мутатор)
                                                        │
                                                        ▼
                              Math core ◄──── state ────► Renderer (canvas)
```

- **UI** — кнопки, ползунки, таблицы. Управляет только `state.*` и вызывает `render()`.
- **Interaction** — `pointerDown / Move / Up / Cancel`. Мутирует `state` (добавляет точки/рёбра, сдвигает view, тащит точки).
- **State** — единственный источник правды. Модель: `points + segments` с ролями.
- **Math core** — чистые функции: `computeVanishingPoints`, `computeValidation`, `getFovInfo`, `drawIdealCube`. Не знают о DOM.
- **Renderer** — единственная функция `render()`. Читает `state`, рисует на canvas, синхронизирует DOM.

### Модель данных

```js
// Точка
{ id: 'p1', x, y, kind: 'free' | 'intersection' | 'onLine' }

// Ребро
{
  id: 's1', aId, bId,
  vertical: bool,
  role: 'start' | 'side' | 'vertical' | 'top'
}
```

**Роль** — ключевая абстракция. Определяет:
- как ребро участвует в математике (`start` — референс, `side` — даёт VP, `vertical` — глубину, `top` — проверяется);
- цвет рёбер при рендере;
- лимит (`side ≤ 4`, `vertical ≤ 2`, `top ≤ 2`).

**Модель минимальна:** всё остальное — производные от неё. Точки схода, горизонт, идеальный куб, метрики — считаются на лету.

### Системы координат

| Система | Где живёт | Что значит |
||||
| **World** | `point.x, point.y` | координаты фигуры |
| **Screen** | `ctx` координаты | пиксели холста |
| **View** | `state.view` | сдвиг пана |

`state.points` всегда в world-координатах. Рендер делает `ctx.translate(view.x, view.y)`. `pointerDown/Move/Up` делают обратное `screenToWorld`.

**Из-за этого панорамирование не искажает математику.**

### `baseW` / `baseH`

«Замороженные» размеры окна. Запоминаются в момент постановки первой точки. Все вычисления FOV, `d`, `cx` идут от них. Ресайз окна не меняет математику — меняется только то, как обрезан холст.

### Инструмент — производная состояния

```js
if (!start)             tool = 'vertical';
else if (side < 4)      tool = 'segment';
else if (vertical < 2)  tool = 'verticalEdge';
else if (top < 2)       tool = 'top';
else                    tool = 'top';  // готово
```

Никакого ручного выбора. Undo автоматически подбирает нужный инструмент через `syncToolWithState()`.

### Undo / Redo

Снапшоты **только** `points` и `segments`:
```js
JSON.stringify({ points: state.points, segments: state.segments })
```

- 50 шагов (ring buffer).
- `saveState()` — в конце каждого логического действия.
- Откатываются только рисунок. `fov`, `view`, режимы — это «параметры просмотра», а не «рисунок».

### Правила снапа

| Инструмент | Начало с пустого места | Начало с точки |
||||
| Боковое ребро | снап к существующим (22px) | без снапа |
| Верхнее ребро | **всегда** снап к ближайшей точке (22px) | то же |
| Вертикаль | снап только точного попадания (< 4px) | то же |

Асимметрия сделана специально: вертикаль не должна «прилипать» к случайным соседним точкам.



## Математика

### Модель камеры

Упрощённая, без наклона/крена:

```
cx = baseW / 2
cy = среднее VP.y  (или одна VP, или baseH/2)
d  = (baseW/2) / tan(fov/2)
```

Проекция `(X, Y, Z)`:
```
x_s = cx + d·X/Z
y_s = cy − d·Y/Z
```

### Точки схода (3 случая)

`computeVanishingPoints()` разбирает:

1. **2/2** — по 2 ребра с каждой стороны. Стандартное пересечение пар.
2. **4/0 или 0/4** — все рёбра ушли в одну сторону (куб у края экрана). Умное паросочетание: пробуем оба разбиения `(top_i, bot_j)`, выбираем то, где оба VP «впереди» своих рёбер (dirScore = 4/4) и с минимальной разницей `y`.
3. **3/1** — паросочетание неоднозначно. VP не вычисляются, в таблице подсказка.

### Формулы метрик

**Пропорции** (`eps_prop`) — ключевая метрика для отличения «куба» от «столба/блина»:

```
k_actual   = (V_bot.y − cy) / (y_bb − cy)        // из экрана
k_expected = 1 + (h_f / d) · cos(ψ)              // для куба
eps_prop   = |k_actual − k_expected| / (k_expected − 1)
```

где `y_bb` — `y`-координата пересечения задней вертикали с боковым ребром снизу, ψ — угол поворота куба.

**Перпендикулярность** (`eps_angle`):

```
eps_angle = |ψ_L + ψ_R − 90°|
```
где `ψ_L = atan((cx − x_L) / d)`, `ψ_R = atan((x_R − cx) / d)`.

В авто-режиме всегда ≈0 — по построению авто-FOV.



## Ограничения

- **Одна центральная проекция**: не поддерживается наклон/крен камеры.
- **`h_f` как референс**: если стартовое ребро короткое (< 5px), валидация становится шумной.
- **Пропорции** работают только когда нарисованы обе вертикали.
- **3/1** (три ребра из четырёх с одной стороны) → VP не вычисляются, паросочетание неоднозначно.
- **Undo** восстанавливает только рисунок, не view/fov/режимы.
- **Нет выделения и группировки** — чтобы переместить куб целиком, таскайте каждую точку отдельно.
- **Нет экспорта** рисунка.


## Как адаптировать под себя

### Изменить пороги валидации

В `updateValPanel`:
```js
row2('Горизонт', pct(v.eps_horizon), rnk(v.eps_horizon, 0.05), ico(v.eps_horizon, 0.05));
//                                                       ↑ порог          ↑ порог
```

### Изменить лимиты рёбер

Константы в начале скрипта:
```js
const MAX_SIDE = 4, MAX_TOP = 2, MAX_VERTICALS = 2;
```

### Изменить FOV по умолчанию

```js
fov: 60,        // в state
autoFov: true,  // и в HTML <input value="60">
```

### Поменять цвета

| Элемент | Стиль |
|||
| Стартовое ребро | `#8affb8` (зелёный) |
| Боковое | `#d8d8ff` (белый) |
| Вертикальное | `#ffb87a` (оранжевый) |
| Верхнее | `#a0e8ff` (голубой) |
| Идеальный куб | `rgba(200, 100, 255, 0.85)` (фиолетовый) |
| Точка свободная | `#7ab8ff` |
| Точка-пересечение | `#a0e8ff` |

### Убрать tap-tap режим

В `pointerUp`:
```js
if (gestureMoved) {
  finishDraft(...);
}
// Добавь:
else {
  cancelDraft();
}
```

### Добавить третью вертикаль или другое ребро

Потребуется:
1. Изменить `MAX_VERTICALS`.
2. Проверить `computeValidation` (там цикл по `getCubeVerticals()`, работает для любого количества).
3. Проверить `ensureIntersectionPoints` — создаёт точки автоматически.
4. Обновить `syncToolWithState` при необходимости.


## Принципы проектирования

1. **Single-file app.** Без `node_modules`, без сборки. Копируется и запускается.
2. **Никаких классов.** Всё на функциях и объектах. Проще для маленькой программы.
3. **Единый `state`.** Легко снапшотить, отлаживать, читать.
4. **Рендер — чистая функция.** `render()` детерминирован, ничего не мутирует.
5. **Производные вычисляются, а не хранятся.** VP, горизонт, метрики — каждый кадр.
6. **Безразмерные метрики.** Все ошибки в процентах от `h_f`.
7. **Математика изолирована от UI.** `computeValidation` не знает о кнопках.
8. **Auto FOV — граничное условие, а не настройка.** Включён по умолчанию.
